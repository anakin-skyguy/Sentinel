# Artistic Direction: Intelligent Bank Fraud Detection Dashboard

---

### Mood & Inspiration

This dashboard lives in the world of the **NOC (Network Operations Center)** — not as it appears in Hollywood thrillers, but as it actually exists: the fluorescent-lit, coffee-stained, deeply serious workspace of people whose job is to see threats before they materialize. Think the control room aesthetic of **Stanley Kubrick's *Dr. Strangelove*** crossed with the raw data density of **Bloomberg Terminal interfaces**, the green-on-dark tension of **Michael Mann's *Heat*** transaction sequences, and the utilitarian precision of **SWIFT network monitoring software** circa 2018. Reference the architecture of **Zaha Hadid's MAXXI museum** — not its curves, but its principle: everything flows, nothing is decorative, form is entirely generated by the movement of information. The emotional register is **controlled urgency**: not alarm-fatigue red everywhere, but a system that is calm until it isn't, where a single color shift carries the weight of a genuine threat. Think underground bunkers, server room hum, the glow of monitors at 3am. This is a tool for people who do not have time to be impressed by it.

### Color Palette

- **Primary — Reactor Teal** `#0ECFB0`
  *Why this, not another:* This is the color of oscilloscope traces and terminal phosphor on dark glass. It reads as "live system" — active, real-time, alive. Not the safe corporate teal of SaaS dashboards; this one has voltage in it. It signals APPROVED states and healthy agent activity without the visual weight of green.

- **Secondary — Graphite Slate** `#1A2332`
  *Why:* The true base of the dark UI — not pure black (which flattens depth) but a deep navy-charcoal that reads as "the room the screen is in." It gives the interface a physical presence, like a hardware console. All data lives on top of this.

- **Accent — Threat Amber** `#F59E0B`
  *Why:* FLAG states, warnings, and mid-risk scores use amber — the color of caution lights in actual security infrastructure. It sits between calm and critical without inducing panic. Chosen specifically over orange because amber has institutional weight (amber alerts, amber warnings in aviation).

- **Destructive/Critical — Breach Crimson** `#E53E3E`
  *Why:* BLOCK states, high-severity fraud hits, and critical agent failures. Reserved exclusively for genuine threats — used sparingly so that when it appears, it is impossible to ignore. The scarcity is the design.

- **Background/Surface Tones:**
  - Base canvas: `#0D1117` (deeper than Graphite Slate — the void behind the panels)
  - Panel surface: `#1A2332`
  - Elevated card/modal: `#222D3E`
  - Subtle border/divider: `#2A3A52`
  - Data row hover: `#1E2D42`

- **Light and Dark Mode Approach:**
  Dark mode is the *canonical* mode — this is not a preference, it is the product. The system is designed for extended use in dim operational environments where light mode would cause eye strain and destroy focus. A light mode should not be offered. If forced by enterprise requirement, it maps to cool grey-white surfaces (`#F0F4F8`) with the same teal/amber/crimson accent system — but the primary design investment is dark.

### Typography

- **Heading Font: [Space Grotesk](https://fonts.google.com/specimen/Space+Grotesk)**
  *Why:* Space Grotesk has the mechanical personality of instrumentation displays — slightly quirky letterforms at large sizes, rigidly legible at small sizes. It reads as "technical precision with a maker's hand." The subtle ink-trap details in letters like 'a' and 'g' feel like circuit board etchings. It is not a corporate font; it is an engineering font. Perfect for KPI values, alert headings, and agent names.

- **Body Font: [IBM Plex Mono](https://fonts.google.com/specimen/IBM+Plex+Mono)**
  *Why:* Transaction IDs, model scores, timestamps, IP addresses, account numbers — all the actual *data* in this system is fundamentally code-like. IBM Plex Mono treats this data with the respect it deserves: monospaced columns align perfectly, scores like `0.847` read as measurements, not decoration. IBM's heritage in financial computing infrastructure is not a coincidence here. For prose labels and descriptions, pair with **IBM Plex Sans** (same family, same visual DNA, different rhythm).

- **Scale & Weight Notes:**
  - KPI values: Space Grotesk, `800` weight, `48px` — these need to hit like physical readouts
  - KPI labels: IBM Plex Sans, `400`, `11px`, `letter-spacing: 0.15em`, ALL CAPS — instrument panel labeling
  - Table data: IBM Plex Mono, `400`, `13px` — absolute consistency
  - Alert/threat headlines: Space Grotesk, `700`, `18-22px`
  - Body copy / tooltips: IBM Plex Sans, `400`, `13px`, line-height `1.6`
  - Status badges: IBM Plex Mono, `600`, `10px`, ALL CAPS, `letter-spacing: 0.1em`

### Voice & Wording

The tone is **clinical precision with zero sentimentality**. Every word earns its place. No marketing language, no congratulatory micro-copy ("Great job! No fraud today!"), no softening of bad news. This system speaks like the instrument it is: factual, immediate, actionable. When something is wrong, it says so plainly. When something needs attention, it names the thing. Analysts reading this UI are under pressure — language that respects their expertise and wastes none of their time.

- **Site title / headline:**
  `SENTINEL` — *Fraud Intelligence Operations*

- **Navigation labels:**
  - `Operations` (main dashboard overview)
  - `Transactions` (full live feed + history)
  - `Agent Network` (JADE agent status and communication graph)
  - `Model Performance` (XGBoost/Isolation Forest metrics)
  - `Incident Log` (reviewed and closed cases)
  - `Configuration` (thresholds, rules, alerts)

- **CTA buttons:**
  - Primary review action: `Investigate`
  - Blocking a transaction: `Confirm Block`
  - Escalating a flagged item: `Escalate to Analyst`
  - Clearing a false positive: `Mark Safe`
  - Acknowledging an alert: `Acknowledge`
  - Exporting data: `Export Report`

- **Empty states:**
  - Live transaction table (no activity): `No transactions in the current window. System is monitoring.`
  - Agent panel (all offline): `Agent network offline. Check WebSocket connection.`
  - Incident log (no closed cases): `No resolved incidents in this period.`
  - Search/filter returns nothing: `No transactions match the current filter criteria.`

- **Section headings:**
  - KPI row: `LIVE METRICS` (label above, small caps)
  - Transaction feed: `TRANSACTION STREAM`
  - Fraud timeline chart: `FRAUD ACTIVITY — 24H`
  - Agent status panel: `AGENT NETWORK STATUS`
  - Model output: `MODEL SCORING`
  - Risk breakdown: `THREAT DISTRIBUTION`
  - Transaction detail modal header: `TRANSACTION DETAIL / [TX_ID]`

### Layout & Structure

**How does the user move through the content?**
The primary experience is a **single persistent dashboard page** — analysts do not navigate away from the live feed. Everything critical is visible simultaneously without scrolling on a standard 1440px widescreen monitor. Secondary views (full transaction history, model performance, agent detail) exist as separate pages reachable from the left nav, but the operations page is the home they never leave.

**Where is the navigation and what form does it take?**
A **narrow, icon-only left sidebar** — `56px` wide in collapsed state, expanding to `220px` on hover. It contains icons for each section with tooltips on collapsed state. Always visible. At the very top: the SENTINEL wordmark as a geometric icon. At the very bottom: system status indicator (green pulse = connected, amber = degraded, red = disconnected) and analyst avatar/logout. The sidebar never competes with the data — it is a rail, not a menu.

**What dominates the first screen?**
The first screen is divided into three horizontal bands:
1. **Top band** (~15% height): Four KPI cards in a row — `Transactions / min`, `Fraud Rate %`, `Blocked Today`, `Active Alerts`. Each card is a dark panel with the value in massive Space Grotesk numerals and a small sparkline trend on the right. The APPROVE/FLAG/BLOCK counts use their respective colors.
2. **Middle band** (~50% height): Split horizontally — left two-thirds is the **live transaction table** (streaming rows, newest at top, color-coded by verdict), right one-third is the **Agent Network Status panel** (6 agent cards, each showing name, current task, message count, status pulse).
3. **Bottom band** (~35% height): Full-width **Fraud Activity — 24H timeline chart** — a dark area chart showing volume of flagged and blocked transactions over time, with hover tooltips on individual spikes.

**What's the structural principle?**
**Strict grid with information hierarchy encoded in panel proportion.** Not cards floating in white space — panels that *tile* the screen like a control room display system. Subtle `1px` borders in `#2A3A52` divide panels. No drop shadows (too decorative), no rounded corners larger than `4px` (this is not a consumer app). The grid is `12-column` but panels span full-width sections within bands, not arbitrary column counts.

**How dense is the content?**
Information-rich by design — but density is *controlled*. The transaction table shows 15 rows without scrolling. Numbers are large where they carry urgency (KPIs), small where they carry data (table rows). Whitespace exists within panels as breathing room, not between them. Think Bloomberg Terminal density *organized* — not a wall of noise but a system where every pixel has a job.

**Transaction Detail Modal:**
Triggered by clicking any table row. Slides in from the right as a `480px` panel — not a full overlay, so the live feed remains visible. Shows full transaction breakdown: parties, amount, timestamp, geolocation flag, XGBoost score, Isolation Forest score, contributing features (SHAP-style bar visualization), which agent flagged it, and action buttons (`Investigate` / `Mark Safe` / `Confirm Block`).

### Signature Element

**The Verdict Badge System with Motion State.**
Every transaction row carries a verdict badge — `APPROVE`, `FLAG`, or `BLOCK` — and the badge does not simply *appear*. When a new row streams in via WebSocket, the badge begins as a neutral grey pulse for `~300ms` (the model is "thinking"), then resolves to its final state with a `clip-path` reveal that wipes left-to-right in `150ms`. BLOCK badges additionally trigger a `2px` crimson left-border on the entire row that flashes once on entry. This choreography — the pause, then the verdict — mirrors the actual computational process happening underneath and makes the system feel *alive and deliberate*, not like a static table. On the agent panel, each agent card has a breathing pulse animation (`scale: 1.0 → 1.03 → 1.0` over `3s ease-in-out`) when actively processing — the dashboard literally breathes with the work being done.

### Anti-Patterns

1. **Do not use red as a general UI color.** Breach Crimson (`#E53E3E`) is reserved exclusively for BLOCK verdicts and critical failures. If it appears on a button, a chart axis, a hover state, or a decorative element, it loses its signal value. The entire threat communication system depends on this color meaning exactly one thing.

2. **Do not animate for delight — animate for information.** No entrance animations that are "cool," no skeleton loaders that pulse artistically, no page transitions that pause the user. Every motion must communicate system state: a spinning indicator means loading, a pulse means live, a flash means new data. Motion that communicates nothing should be removed.

3. **Do not soften the data with rounded UI conventions.** Large border-radius, card shadows, pastel backgrounds, emoji in status labels, or celebratory empty states ("🎉 All clear!") are a category error. This is security infrastructure. The visual language must match the weight of what it displays — a rounded pill badge on a BLOCK alert is a UX lie.

4. **Do not let the agent panel become a decorative widget.** The 6 JADE agents are the computational engine of the system. Their panel must show real state: current task, last message sent, processing latency, error states. If it becomes an aesthetic "6 circles with names," it provides no operational value and trains analysts to ignore it.

5. **Do not paginate the live transaction table.** Pagination implies the analyst is "done" with a set of transactions and moving to the next batch. The feed is continuous. Implement **virtualized infinite scroll** with a "jump to live" button when the analyst has scrolled back in history — the stream never stops, and the interface must reflect that ontological reality.
